# SIH 2026 · PS 26175 — DepthWizard

Everything decided, measured and observed so far. Start here.

## The 30-second version

One flat photo taken from a satellite looking straight down. You can see roofs, trees and
roads; you have no idea how tall anything is. **DepthWizard turns that single image into
height numbers, then into a 3D city you can fly through.**

The output is a **DSM** — the same grid of pixels, but each pixel holds an elevation in
metres instead of a colour. Open it as a greyscale image and it looks like an X-ray of the
city's height: white for a tower, grey for a house, black for the road. Then the viewer
builds real 3D terrain from that grid and drapes the original photo over it, so you can
fly through, click a roof, and read its height.

Sponsor is **ISRO**, under the Disaster Management theme. Marks are **50% accuracy,
50% visualization** — a beautiful flythrough with no measured accuracy scores half, and so
does an accurate model with no usable viewer.

## The five things that decide this

1. **The domain gap is real and must be measured, not assumed.** Pre-trained depth models
   are built for egocentric photos. On a nadir orthophoto they partly report brightness as
   depth. Phase 1 measures exactly how bad that is, and that number is an asset.
2. **Relative depth carries no metres.** Converting it is the brief's stated core
   challenge. We attack it three ways — SRTM terrain, shadow geometry, GCP fitting — and
   measure each independently.
3. **Stratified reporting is a requirement, not a courtesy.** The brief asks for stability
   across urban, sparse, hilly and forested. One average does not satisfy it.
4. **The viewer is half the marks.** Including "standalone deployment", which is named in
   both the milestones and the criteria.
5. **We are evaluated on imagery we have never seen,** from a different country and a
   different sensor. Anything tuned until it looks good on our own tiles is worthless.

## The one architectural rule

**Terrain and objects are estimated separately, and never confused.**

```
DSM  =  DTM  +  nDSM
        SRTM    predicted
```

Nothing in a single image encodes absolute elevation above sea level — so we do not ask
the network for it. SRTM supplies the terrain it is good at; the network supplies the
object heights it is good at. This is also what the recommended dataset does: GAMUS ships
its height layer as **AGL (above ground level)**, so the officially recommended training
data trains the nDSM term specifically. Full reasoning in `05-domain-reference.md`.

## Start here, today

Phase 0 is the live work. Nothing below needs the model to exist:

1. **Fix CUDA.** torch is installed as the **CPU build** — `torch.cuda.is_available()` is
   `False` on a machine with an RTX 4060. `pip install torch --index-url
   https://download.pytorch.org/whl/cu130` (2.13.0+cu130 exists and matches the installed
   version). Until this is done every timing number is meaningless.
2. **Start the GAMUS download** — ~80 GB, the longest lead time in the project. Background
   it now; it does not block Phase 1 code.
3. **Find terrain-diverse supplementary data.** The GAMUS mirror is three flat US cities.
   Half the brief's stability requirement cannot be evidenced without hilly and forested
   data. This is the biggest open risk — see `11-deferred.md`.
4. **Resolve the GAMUS class legend** empirically (cross-tabulate class index against AGL
   statistics). Six class names are known; their index order is not.
5. **Obtain real ISRO sample imagery at two different GSDs** to exercise GSD handling
   against something real rather than a resampled proxy.
6. **Settle SRTM access** — OpenTopography API key versus direct tile download.
